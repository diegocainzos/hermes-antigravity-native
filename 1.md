### 2.2. Root cause del 403 (y de por qué el plugin viejo falla)

`403 Cloud Code Private API has not been used in project <NUM>` donde `<NUM>`
(= `1052827114944`) es la parte numérica del **OAuth client_id** del plugin viejo. Su
proyecto Google Cloud no tiene habilitada la API. Fix oficial documentado (ver skill
`hermes-oauth-model-plugin-setup`): habilitar
`https://console.developers.google.com/apis/api/cloudcode-pa.googleapis.com/overview?project=1052827114944`.
Con el token de agy ese error desaparece (agl no viaja por ese client).

### 2.3. Path de streaming con token de agy — verificadísimo OK

Probe real que SÍ funcionó (antes de que el access token de agy expirara):
`probe_stream.py` → `stream_generate` con `token=agy.access_token`, `project=aicode-consumers`,
`model=gemini-3.8-flash-low` → **`streamed OK, "OK"`**. El código de streaming del plugin
(URL, endpoint, envelope, SSE) es correcto. El único motivo de 401 es que el access token
del archivo de agy **caduca** (~1h) y solo agy lo re-emite cuando se ejecuta
(`agy -p "...` lo refresca; toca `token.expiry`/mtime). El plugin no puede refrescar ese
token in-process (client privado de agy).

Al usar el client 1052 (via `antigravity-accounts.json`) el streaming da 403 (API

### 2.5. Gap: `--provider antigravity-native` no resuelve en `hermes -z`

`get_provider_profile('antigravity-native')` SÍ lo encuentra (registry de
`providers/__init__.py`), pero la vía CLI `hermes -z --provider antigravity-native`
falla con `Unknown provider`. La resolución CLI pasa por `resolve_provider_full`
(`hermes_cli/providers.py`) / `hermes_cli/auth.py::resolve_provider`, que usan un
catálogo distinto al registry de `ProviderProfile`. El plugin viejo sorteaba esto
parcheando el picker/aliases (no copiar esa vía). Queda por resolver cómo seleccionarlo
de forma limpia (config custom provider apuntando a `http://127.0.0.1:51789/v1`, o
registrar alias/entrada en el catálogo, o `hermes model` interactivo).

## 5. Resultado de las TAREAS (Claude Code, 14-Oct-2026) — verificado en vivo

**Errata de §2.1/§2.3:** el token de agy lo emitió el cliente público `1071006060591…`
(`aud` de su `id_token`), el mismo que pi y que el default del plugin. El refresh in-process
**sí funciona** con el secret real (`…K58FWR486…`; la prueba anterior usaba `…448…` y además
`client_id()` elegía siempre el 1052 del plugin viejo). Token refrescado → `streamed "pong"`.

1. **Credenciales**: cada fuente lleva su cliente OAuth; orden env → login propio → agy →
   accounts(1052) → google_oauth. Refresh in-process sin `agy`. Doctor: todo PASS.
2. **Selección**: `Unknown provider` venía de que el plugin viejo `antigravity` importa
   `hermes_cli.auth` durante el discovery y congela `PROVIDER_REGISTRY` antes de que cargue el
   nuestro (orden alfabético). Wrapper renombrado a `0-antigravity-native`. `hermes -z
   --provider`, `hermes model` y `/model <m>` resuelven. `/model --provider` desde otro provider
   no: `resolve_provider_full` del core no consulta providers de plugins (igual con
   `google-gemini-cli`).
3. **Store propio**: solo lo escribe `login` (v2 con `clientId`); refrescos ajenos → caché por
   huella del refresh token. Stores pre-v2 se ignoran.
4. **401**: refresh forzado + 1 reintento; luego error accionable. Expiry sin refresh posible →
   mensaje con fuente, causa y `login`/`agy`.
5. **Tests**: 145 passed (112 originales + nuevos).
6. **Plugin viejo**: su hook global de `httpx.Client.send` quitaba nuestro `Authorization`
   (→ 401). Las peticiones nativas llevan sus marcadores de "ya procesado" y las ignora.
7. **Bloqueo nuevo encontrado**: el backend responde `429 RESOURCE_EXHAUSTED` (no es cuota) a
   cualquier system prompt con la frase de identidad de Hermes
   (`You are Hermes Agent, an intelligent AI assistant created by Nous Research`). Es
   determinista y ocurre con Gemini y Claude. El pipeline completo (17 tools de Hermes, SSE,
   tool calls) funciona sin esa frase.
8. **Enmascarado de identidad (opt-in del usuario)**: `transform.build_request` sustituye esa
   frase por una línea neutra de coding assistant solo en el tráfico de `antigravity-native`.
   Se controla con `ANTIGRAVITY_NATIVE_MASK_IDENTITY` (por defecto `1`), deja un WARNING y
   aparece en `doctor`. Verificado en vivo: `hermes -z ... --provider antigravity-native`
   responde con el valor por defecto `1` y da 429 con `0`. Tests: 154 passed.
